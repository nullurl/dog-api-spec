# 表情渲染几何笔记

改 `assets/js/expression.js` 的几何之前读这份。它是踩坑记录，不是教程。

正文 §4.6 定义的是**接口**；这里记的是把那个接口渲染成 24×24 像素时踩过的坑。

## 坐标系与栅格

- 输出是 `N = 24` 的方阵。SVG `viewBox="0 0 24 24"`，`shape-rendering="crispEdges"`，坐标全为整数。
- 调色板 11 色，单字符键：`O` 外轮廓、`D` 深色、`F` 面部底色、`L` 亮部、`N` 鼻、`W` 眼白、`P` 瞳、
  `T` 牙/舌、`B` 颊、`K` 深口、`M` 运动残影。
- 只有 `SILHOUETTE = {F, D, L, N, T}` 会被描一圈外轮廓。**运动残影 `M` 刻意不在这个集合里** ——
  否则每道残影都会自带一圈黑边，看起来像三只叠在一起的狗。

## 超椭圆，以及颅顶的尖角

头部与耳朵用超椭圆填充：

```
|dx/rx|^n + |dy/ry|^n <= 1
```

`n = 2` 是椭圆（在 24px 下圆得没有性格），`n` 越大越接近圆角矩形。
**head 用 `n ≈ 3.4`，耳朵用 `n ≈ 2.3–3.4`。** 超过约 3.6 之后颅顶会在整数栅格上崩出一个尖角，
而且那个尖角会随 `tilt` 一帧一帧地跳。这是本项目最容易被误判为「抗锯齿问题」的 bug。

顺手记一下：**这里曾经有一个优先级 bug** —— 第二项写成了 `Math.pow(Math.abs(dx)/ry, p)`（用了 `dx` 而不是 `dy`）。
它不会报错，只会让图形在旋转时慢慢变形。改这段代码时先确认变量名。

## 旋转（tilt）

`transformPair(tilt)` 返回 `{fwd, inv}`：`fwd` 把模型坐标旋到画布，`inv` 反过来。
所有几何在**模型坐标**里定义，采样时用 `inv` 把画布点映射回模型空间再判定 —— 这叫反向采样，
比「先画再整体旋转」稳，因为它不产生空隙。

**坑**：判定椭圆时用的 `dy` 必须是**旋转后**的 `qy`。用未旋转的 `dy` 会让头朝反方向歪 ——
图形照样好看，只是它在看另一边。

## 耳廓与颅顶的缺口

耳朵根部与颅骨在中间档位（`earPerk ≈ 0.5`）会留出一个楔形缺口：

```
baseCx = 4.6 - earBack * 0.6
baseCy = 8.6 - earPerk * 1.9 + earBack * 0.9
```

修法是在耳根补一个椭圆把缺口填上（`rootCx = 6.5`、`rootCy = 8.4`），并把 head 提到 `n = 3.4`。
只调其中一个不够。

## 眉毛与眼睛

```
innerX = cx - s * 1.45
outerX = cx + s * 1.65
baseY  = 9.0 … 9.5
lift   = browInner * 1.45        // 负值 = 向下压
```

- 早期版本眉毛太宽，会伸进耳廓里，看起来像两根触角。
- **`eyeOpen < 0.16` 时必须跳过眉毛。** 这是 `SLEEP` 修复的关键：闭眼时眼睑画在 `cy + 0.55·sin`，
  高度正好落在眉毛基线 `baseY = 8.9` 上，两者一叠就是「睡着但眉毛画歪了」。同时把眼 `cy` 降到 12.5、
  眉毛基线抬到 9.0。
- 瞳孔偏移量要比直觉小 —— 24px 下偏移 1 格就已经是「眼睛跑到眼角」了。

## 鼻与嘴

- 鼻 `cy ≈ 16.4–16.5`，嘴弧 `cy ≈ 19.4–19.55`。**这两者之间的空隙必须保住**，
  一旦鼻子上移 0.3 就会和嘴连成一团。
- 嘴弧用 `19.55 + Math.sin(πt) * 0.45`、半宽 `0.60`。斜率再陡一点，0.55 宽的线就会在栅格上断成
  几段互不相连的墨点 —— 看上去像坏掉的传真机。
- 舌宽 `(0.95 + tongue * 1.05) * (0.55 + open * 0.45)`。

## UNKNOWN 剪影

剪影**不能**用「先填实、再腐蚀内部」的做法：那样会留下一圈孤立斑点。
正确做法是收集实心集合 `{F, D, L}`，对每个实心格检查四邻，只要有一个邻格不属于实心集合就标成 `O`，否则标 `.`。

问号画在**颅顶正中上方**（x 10.2–13.0，y 1.9–5.9）。两耳之间只有这一块干净地方，
挪到任一侧都会跟耳廓剪影叠在一起。

## 为什么是运程合并

`toSVG` 按颜色做水平行程合并：`M{x} {y}h{w}v1h-{w}z`，每色只出一条 `path`。
14 帧实测 **757 B – 2 372 B，均值约 1 785 B**（`scale=12`）。逐像素出 `<rect>` 会大 4–6 倍。

## 改完之后必须跑

```bash
node scripts/expression.js --selftest        # 引擎断言，含 SICK=基线、UNKNOWN=剪影、compose 409
node scripts/expression.js --all --out /tmp/x
node -e "..."                                  # 或直接用 XML 解析器校验 /tmp/x/*.svg
```

XML 校验要覆盖：`<svg>` 闭合、`path` 的 `d` 以 `M` 开头、无 `NaN` / `undefined` / `None`、
点阵行数 = 24、矩阵行数与列数 = 24。

`--selftest` 里最关键的一条是 **SICK 的像素必须与 `BASE` 完全一致**
（只比 `<path>`，`data-state` 和 `aria-label` 按设计就是不同的）。
这条断言是 DOG API §4.6 的核心声明，它被破坏时不会有任何别的症状。

## 已知的非 bug

- 终端里 `--list` / `--params` 的中文列宽由 `pad()` 手工按 CJK 双宽计算。改字体不影响它，
  改内容才影响。
- `toDataURI` 会把 `%20` / `%3D` / `%3A` / `%2F` / `%22` 还原成字面量 —— 为了可读性，
  不是 bug。
- `--compose` 的「不可保持」帧仍然可以渲染（加 `--svg`）。409 说的是「它保持不住」，
  不是说「渲染不出来」。
