# 量化模型说明（dog-quant/v1）

> 本文是 §4.5 量化接口定义的工程说明。它回答一个问题：**文档里那些数字，是怎么算出来的。**

对应代码：

| 文件 | 作用 |
| --- | --- |
| `assets/js/quantify.js` | 计算内核。纯函数，浏览器与 Node 通用，无依赖 |
| `assets/js/scenarios.js` | 场景库。14 个场景 / 69 个步骤 / 38 条量化门槛 |
| `tools/quantifier.html` | 交互式评估器。页面上的数字全部由内核实算，无硬编码 |
| `spec/quantified-api.yaml` | 端点与数据结构的机器可读描述 |
| `reference/vitals.html` | 生理指标速查（正文 §4.2 的合并视图） |

---

## 1. 三条设计原则

1. **每个指标必须声明四件事**：单位、取值范围、采样频率、报警阈值。
2. **每个指标必须标注来源等级**：`A` / `B` / `C`。
3. **分诊优先级高于一切评分**：分诊结果为 `P0` 或 `P1` 时，所有评分端点短路返回 `451`。

第 3 条是这套方案唯一强制性的设计。它的理由是：量化的第一原则是知道什么情况下应该停止量化。

---

## 2. 来源等级

| 等级 | 含义 | 本方案中的实例 |
| --- | --- | --- |
| **A** | 同行评议文献或大规模实测数据 | 表观遗传钟 `16·ln(a)+31`；4,804 只犬的血液 95% 参考区间；静息呼吸阈值；Glasgow CMPS-SF 疼痛量表 |
| **B** | 临床指南或专业机构共识 | 体温 / 心率 / 呼吸参考区间；AAHA 生命阶段与免疫指南；老年期 = 预期寿命 × 0.75 |
| **C** | 社区经验或本项目定义的复合指标 | 幼犬「月龄 × 5 分钟」；嗅闻 1:3 换算的具体倍数；`DNS` / `HRI` / `VSI` 三个评分模型 |

当前分布：**A 级 7 项 · B 级 11 项 · C 级 8 项**（注册表见 `quantify.js` 的 `PARAMS`，共 26 条）。

`C` 级不等于错，只等于「没有被验证过」。工程含义是：C 级指标可以照做，但不应被引用为研究结论。

---

## 3. 派生指标公式

| 指标 | 公式 | 单位 | 等级 |
| --- | --- | --- | --- |
| 静息能量需求 `RER` | `70 × BW^0.75` | kcal/日 | B |
| 维持能量需求 `DER` | `k × RER` | kcal/日 | B |
| 每日饮水 | `50–60 × BW`，与 `1 mL ≈ 1 kcal` 互校 | mL/日 | B |
| 嗅闻配额 | `20 + 品种加成(±10) + 年龄修正(±5)`，收敛到 10–40 | min/日 | C |
| 运动配额 | 品种类分档 25–90，再乘体况与疾病修正 | min/日 | C |
| 幼犬单次上限 | `5 × 月龄` | min/次 | C |
| 人类年龄换算 | `16 × ln(age) + 31`（`<1` 岁用项目插值 `31 × a^0.62`） | 人年 | A / C |
| 预期寿命 | `16.7 − 2.17 × ln(BW)` | 年 | A |
| 老年期起点 | `预期寿命 × 0.75`；终末 `× 0.90` | 年 | B |
| 年体检次数 | 幼犬由免疫序列决定 / 成犬 1 / 老年 2 / 慢病 4 | 次/年 | B |
| 热调整步行 | `运动配额 × clamp(1 − HRI/20, 0, 1)` | min/日 | C |

`k` 值表（`DER` 系数）见正文 §3.7 喂食接口；幼犬 `<4` 月为 `2.5–3.0`，绝育成犬 `1.4–1.6`，工作犬最高 `5.0–11.0`。

`<1` 岁的年龄换算分支是本项目的插值（C 级）。原始表观遗传钟适用于成年个体，而 `1 岁 ≈ 31 人年` 这条锚点是公开结论，因此幼犬段用幂函数连接，仅用于保持一致，不应用于任何严肃讨论。

## 4. 评分模型

### 4.1 DNS — 日常需求达成度（0–100，C 级）

```
单维得分 = min(实际 / 目标, 1) × 100
总分     = Σ (单维得分 × 权重)
短板封顶 = 若任一维度 < 60 → 总分 = min(总分, 79)
```

| 维度 | 权重 | 目标 |
| --- | --- | --- |
| 运动 | 25% | 25–90 min（品种类分档 + 体况修正） |
| 嗅闻 | 20% | 20–40 min |
| 社交 / 陪伴 | 20% | 60 min 直接互动（共处一室不计入） |
| 休息 | 20% | 成犬 13 h / 幼犬 18 h / 老年 16 h |
| 认知 / 咀嚼 | 15% | 15 min |

分档：`≥85` 达标 · `70–84` 轻度不足 · `50–69` 明显不足 · `<50` 结构性不足。

**为什么需要短板封顶**：把散步从 40 分钟加到 80 分钟，无法补偿一整天没人跟它说话。加权平均会让这类缺口被其他维度的高分掩盖，所以用一条硬规则把它捞出来。

### 4.2 HRI — 热风险指数（无量纲，C 级）

```
气温项     max(0, T − 22) × 0.6          每摄氏度 0.6 点
湿度项     max(0, RH − 40) × 0.15         每百分点 0.15 点
日光直射   +3
短鼻结构   +4
双层/厚被毛 +1.5        深色被毛 +0.5
体重 >25kg +1           年龄极端（<6月 或 老年）+1
热适应     未适应 +2 ／ 近 7 日户外充分 −2
```

分档：`<0` 安全 · `0–5` 注意（时长 ×0.7）· `5–10` 警告（≤50%）· `10–15` 危险（取消户外）· `≥15` 极端（仅排泄）。

**硬性规则（不依赖指数）**：

- 气温 ≥ 32 °C 或 HRI ≥ 10 → 取消户外运动
- 任何天气、任何时长 → 车辆不得作为暂存环境
- 地面判定 → 手背贴地 5 秒；无法忍受即不可出行

`HRI` 是本项目定义的复合指标，**不是临床量表**。它的用途只有一个：把「今天该不该出门」从感觉变成一次可复核的计算。

### 4.3 VSI — 就诊应激指数（0–10，C 级）

累加项：车程 `>20 min +1`（`>40 min +2`）· 既往负性经历 `+2` · 基线焦虑 `+2` · 未做过快乐到访 `+1.5` · 未做嘴套预适应 `+1` · 未用信息素 `+1` · 维护者紧张 `+1`。

减项：已用就诊前药物 `−1.5`（须兽医处方）· 空腹到院 `−0.5` · 车内等待 `−1`。

分档与流程强度：`0–3` 常规 · `4–6` 偏高（快乐到访 + 信息素 + 车内等待）· `7–8` 高（讨论用药、嘴套预适应、要求地板检查）· `≥9` 极高（必须走用药方案，考虑拆分就诊）。

**分数只决定流程强度，不决定去不去。** 它不会因为紧张而不用看病。

## 5. 分诊矩阵

| 优先级 | 时限 | 代表条目 |
| --- | --- | --- |
| `P0` | 立即（分钟级） | 腹部膨隆 + 干呕无物；抽搐；虚脱；张口呼吸伴用力或静息呼吸 >40；牙龈苍白 / 发绀；体温 ≥41 °C；无法止住的出血；误食毒物；公犬无尿；眼球外伤；钝性创伤 |
| `P1` | 当日（小时级） | 静息呼吸 30–40；拒食 >24 h；呕吐 / 腹泻 >2 次/日或带血；体温 39.5–41 °C；单肢不敢负重；疼痛评分 ≥6/24；突然变安静 |
| `P2` | 72 小时内 | 轻度跛行；耳道异味；持续瘙痒；30 日体重下降 >5%；饮水 >100 mL/kg/日；口腔异味 |
| `P3` | 常规 | 疫苗 / 驱虫到期；体检；指甲过长 |

三条操作规则：

1. **取最高级**。同时命中 P1 与 P2 时按 P1 处理，不要平均。
2. **P0 时不要先在家算分、不要先查资料、不要先观察**。最有效的现场处置通常只有一个动作：开车。
3. **拿不准的按更高级别处理**。分诊错误的方向应当单调 —— 把 P3 误判成 P1 的代价是一次多余的挂号费，反过来没有上限。

## 6. 排程生成

### 免疫序列

输入出生日期与今日日期，输出每个窗口的起止与当前状态（`未到期` / `在窗口内` / `窗口已过`）。

关键约束：**末剂 DHPP 必须在 ≥16 周龄接种**，这是整个序列唯一不可提前的一针。理由是数学 —— 没有人知道母源抗体在哪一天失效，因此用 16 周作为兜底。免疫生效还要再等 `7–10` 天。

这就是本规范著名的两难：社会化窗口（`3–14` 周）与免疫空窗期重叠。通行解法不是二选一，而是换介质。

### 寄生虫预防

体内驱虫（幼犬 `2 周龄起每 2 周` → `12 周–6 月每月` → `成犬每 3 个月`）· 体外驱虫（`8 周龄起每月，全年`）· 心丝虫预防（`不晚于 8 周龄起，每月`）· 粪便检查（幼犬首年数次，成犬每年至少 1 次）。

三条硬提醒：不用人用驱虫药；滴剂点在肩胛之间且 24–48 h 内不洗澡；多宠物家庭需同时驱虫。

> 按体重给药这句话里，「体重」是**当下**体重。幼犬每周都在变，用三个月前的数字给药，是这类事故最常见的起因。

---

## 7. 使用限制

1. 所有评分是**偏差提示**，不是诊断。
2. 复合指标（`DNS` / `HRI` / `VSI`）**不得用于横向比较不同个体**，它们只用于同一只狗的纵向趋势。
3. `P0` / `P1` 时不要先算分。
4. 任何健康决策请遵循执业兽医意见。本项目是一份玩笑文体的技术文档，不是饲养指南 —— 唯一例外是那些标注了 A 级的参数，它们有出处，可以查证。

## 8. 如何验证这套东西没算错

```bash
# 语法
node --check assets/js/quantify.js
node --check assets/js/scenarios.js

# 公式断言（RER / 人类年龄 / 寿命 / 分诊 / 封顶规则）
node -e '
const Q = require("./assets/js/quantify.js");
console.log(Q.rer(12.5));                       // 70 × 12.5^0.75
console.log(Q.util.humanYears(4));              // 16·ln4 + 31
console.log(Q.util.lifeExpectancy(12.5));       // 16.7 − 2.17·ln12.5
console.log(Q.triage({ gdv: true }).code);      // P0
console.log(Q.triage({}).code);                 // P3
'
```

评估器页面（`tools/quantifier.html`）底部的参数注册表直接读取 `DogQuant.PARAMS` 渲染，因此**文档与引擎不会出现两套数字**。若两者不一致，以引擎为准 —— 因为它才是被断言覆盖的那一份。
