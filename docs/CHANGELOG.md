## [0.17] — Adoption Widget

**Change class:** Interface

**背景**
0.16 把「安装即授权」立成了规范，但入口只有一张静态卡片：点开是工具页，规则在正文里，
命令要自己抄。**规则在那里，动作不在这里。** 这一版把安装、三态、派生三件事收进一个组件，
放在首页 —— 领养这件事，应该在读者第一次到达的那一页就能做完。

**首页领养组件**（`assets/js/adoption-widget.js`，挂在 `index.html` 的 `#adoption-widget`）
- **自包含**：自带样式（只注入一次）、自带骨架、自带事件绑定。首页只给一个空容器与一行
  `<script>`，其余全在组件里；换页面只需在容器上写 `data-root="../"`，或者 `mount()` 一下
- **步骤 1 · 安装**：命令块与 `skill/SKILL.md` 里那一段逐字一致，一键复制。授权三态
  （未安装 / 已安装 / 已卸载）可切换，每态给一句定义级说明与状态徽标 —— 安装即同意，
  卸载即撤回，中间没有第三种状态
- **步骤 2 · 派生**：四个字段实时算出 KEY，附「用当前时刻」「复制 KEY」「复制元组」
- **它不检测本机。** 页面既没有这个权限，也没有这个必要 —— 三态是技能商店模型，不是状态探针。
  这句话直接印在组件里，免得有人以为它读了本机。授权发生在安装那一刻，不发生在这一页上
- 组件默认停在**出厂元组**上，因此首页一打开就实测了一次「元组相同 → KEY 相同」，
  并与 §5.3 的测试向量 1 逐字节比对，结果直接显示在 KEY 下方

**无脚本回退**
- `#adoption-widget` 里先放一段静态文字（指向工具页与 §5.3），组件挂载时覆盖它。
  JavaScript 没跑起来时，首页仍然有可读的入口，而不是一个空洞

**事实源**
- 安装命令（`CMD`）、三态文案（`STATES`）、出厂元组（`DEFAULTS`）只在 `adoption-widget.js` 里
  定义一次；首页组件与 `tools/adoption.html` 是它的两个消费者。约定写进 `docs/CONTRIBUTING.md` 第 15 条
  （顺手把错位的第 13、14 条按编号排好）
- 首页 hero 加了「领养 KEY」按钮，直达组件锚点；`#adoption-widget` 带 `scroll-margin-top`，
  免得滚动时被吸顶导航盖住

**校验**
- 19 个 HTML / 120 条本地链接全部可达；标签配平；41 个文件 190 处 `§` 引用全部有效
- 渲染冒烟 **36 项**通过（较 0.16 新增 10 项）：首页组件在 DOM 桩里实跑 —— 三态按钮 3 个、
  命令块含 `curl` 与 `dog_adopt.py`、**算出的 KEY 等于 §5.3 测试向量 1**、自检显示一致、
  元组四行已渲染、无 `undefined` 残留。「首页存在」也列成断言：线上回放漏抓 `index.html`
  会直接判失败，而不是跳过

## [0.16] — Authorization

**Change class:** Content

**背景**
本项目一直要求「每个数字都有出处」，0.15 又把口吻立成了规范 —— 但**这份文档自己凭什么在读者手上**，
从来没有写过。同时项目里存在一条早就埋好的矛盾：`§2.2 错误码` 声明本系统**不返回 `401 Unauthorized`**、
对所有 Human 默认全量授权。既然没有拒绝这个动作，任何「授权」设计都不可能是一把钥匙。
这一版按这个前提把话说清楚，并给它一个可执行的形态。

**§5.3《领养与授权（Adoption API v1）》**（追加为 PART V 末章）
- 定位不是权限表，是**来源表**。领养 KEY 是狗牌，不是通行证：牌不负责拦住谁，
  它负责在一只狗走丢之后让捡到的人知道该打哪个电话
- **KEY 不是发放的，是派生的。** 没有发号中心、没有账号、没有服务端 —— 它只能被算出来。
  与表情接口同一条原则：不生成，只编码
- 领养元组四行（`adopter` / `cohort` / `habitat` / `intent`）。规范化只做两件事：折叠空白、去掉首尾。
  **MUST NOT** 做大小写折叠或 Unicode 归一化 —— 做多了会让同一个元组在不同实现里算出两个 KEY，
  而这种分歧不会报错，只会静默地产生第二张证
- 载荷 15 字节 = 版本 1 + 领养秒 4 + 摘要前 8 + 校验位 2，恰好编成 24 个 Crockford 字符，
  因此没有补位、没有歧义
- **授权三态**借用技能商店模型：未安装 / 已安装 / 已卸载。安装即同意，卸载即撤回，中间没有第三种状态
- 「不授予什么」一表 6 项，逐条钉在既有声明上：商用权、饲养指导、医疗判断、故障上报权、转让与转售、匿名
- 有效期与回收：**没有回收通道**。没有签发方，就没有可以宣布它失效的权威

**可核验性（本章唯一可机械检查的部分）**
- 三级，强度差别很大：校验位（只查抄错）、复算（有元组则逐字节确定）、形制（长度与字母表）。
  **没有任何一级能说明「这只狗是谁的」**
- 公布**三组固定测试向量**，任何一份实现 —— 页面里的、命令行里的、别人写的 —— 都 MUST 复现
- 校验位强度有实测出处：对 200 个元组穷举 24 个位置 × 31 种替换字符 = **148,800 次单字符替换，
  漏检 1 次**，即 6.7×10⁻⁶，与 16 bit 的 1/65,536（约 1.5×10⁻⁵）同一量级

**新增**
- `skill/`（`SKILL.md` + `dog_adopt.py`）—— 可安装的领养技能。纯标准库、不联网、只写一个路径。
  安装即授权；证书写在技能目录**之外**（`~/.workbuddy/dog-api/adoption.json`），
  因此卸载技能不会删掉证书
- `assets/js/adoption-key.js` —— 零依赖的派生内核（纯 JS SHA-256 + Crockford Base32）。
  与 `dog_adopt.py` 是同一份规范的两处实现，互为裁判，判据就是 §5.3 的测试向量
- `tools/adoption.html` —— 浏览器内派生与核验，含测试向量自查（4 / 4）。
  页面把「一个不需要授权就能打开的页面算出了 KEY」写成**论据**而不是免责声明：
  这恰恰说明它从来就不是权限。NAV 条目 14 → 15

**节号**
- 新章**追加在 PART V 末尾**，既有 34 章的节号一处未动，全站 `§` 引用无需改写

**校验**
- 19 个 HTML / 118 条本地链接全部可达；标签配平；40 个文件 182 处 `§` 引用全部有效
- 渲染冒烟 **26 项**通过（较 0.15 新增 6 项：导航须含 `adoption.html`，以及领养页在 DOM 桩里
  实跑内联脚本的 5 项断言 —— 该页的正确性只能靠测试向量钉住）
- **交叉验证**：500 组元组（含中文、全角空格、空值、首尾空白、反斜杠路径、大小写混合）在
  Python 与 JS 两份实现上**逐字节一致**
- `python3 skill/dog_adopt.py --selftest` 9 项通过

## [0.15] — Voice

**Change class:** Content

**背景**
项目从 0.1 起就用工程文体处理一种没有说明书的系统，但**口吻一直是隐性的** ——
它存在于每一章里，却没有一处写下来。结果是改文字的人只能靠模仿，
而模仿最容易学到的是错的那部分：把语气写强、把笑点点出来、往句尾补一句总结。

这一版把口吻写成规范，并补上它一直缺的那半个声音。

**双声部**
- 新增 `reference/voice.html`《口吻与文体》。全站只有两个声部，权限不重叠：
  **规范编写组**（第三人称，有文献与来源等级，可以下 MUST，不许抒情），以及
  **当事人**（第一人称，没有依据只有结论，不许给建议、不许引用文献、不许解释自己）
- 第二声部在正文中的形态定为**以「本机：」开头的引用块**。正文里本来就有「规范提示：」
  「运维建议：」「诚实性声明：」这类带署名的引用块，「本机：」只是把署名交给当事人
- 当事人声部的三条装置：**自我暴露**（有利益、有短处、原则可议价）、
  **民族志距离**（把人类当作只被观测、不被理解的外部系统来记录）、
  **格言收尾**（一句一条，说完就停在那里）。三条各配一组正反示例
- 规范编写组声部的四条硬约束：事实在前 / 不解释笑点 / 不替它抒情 / 不越过兽医
- 新增**抒情配额**：全站允许的升格句极少，且每一句 MUST 由一个已经陈述过的事实支撑。
  配额不给数字给原则：一章之内至多一句，一章没有更好
- 新增**一票否决**表：感叹号、自评有趣、解释性连词、形容词化的评价、饲养建议、
  把行为写成"爱" —— 在正文中出现即回退重写，与句子好坏无关

**新增页面**
- `reference/opinions.html`《一只狗的生活意见》：第二声部的完整作品，31 条意见分五组 ——
  关于人 / 关于自己 / 关于食物 / 关于时间 / 关于这份规范
- 两页需同时读：一页**定义**口吻，一页**使用**口吻。均已进顶部导航（NAV 条目 12 → 14）

**正文改动（仅两处，不新增章节）**
- §3.1（未公开行为规范）：在「愧疚脸」一节之后补一条当事人自述 —— 它承认那个表情不是后悔
- §3.9（与人类的互操作）：在 POWER CHECK 之前新增《本机侧记录》一节。它不动该章的测量结论，
  只从内部否掉那个结论可能带来的体面：<em>我没有提出过任何要求，
  因为我手里没有可以用来提要求的东西。这不是美德，这是配置。</em>
- 两处都未新增、删除或重排**章节**，因此节号无一处平移，全站 `§` 引用无需改动

**体裁来源**
- 口吻参照《一只狗的生活意见》（彼得·梅尔 著，廖月娟 译，新世界出版社，1998）。
  只取体裁与手法 —— 当事人视角、格言体、自我暴露、以民族志距离观察人类，不转载原文
- **它不进 §5.1 的信源登记**：那一章登记的是"可以被核验的事实"，本页取的是文体。两者不混

**校验**
- 18 个 HTML / 110 条本地链接全部可达；标签配平；37 个文件 156 处 `§` 引用全部有效
- 渲染冒烟 20 项通过（较 0.14 新增两条：导航须含 `voice.html` 与 `opinions.html`）；
  线上回放跑同一套断言
- 两处正文改动经序列化前后比对，确认**只有 §3.1 与 §3.9 的 html 长度变化**，
  章节数与 id 序列均未动

## [0.14] — Versions & Identity

**Change class:** Provenance

**背景**
此前这个项目**没有任何历史存档**：本文件列了 15 个版本，git 里只有 2 个提交，
0.1 到 0.12 任何一个版本的状态都取不回来。同时，全站的章节引用靠的是**节号** ——
而节号由运行时按数组顺序生成，任何一次插入或删除都会让其后的编号整体平移。

这一版补两件事：把已有的历史形态**冻起来**，以及给每个章节一个**不随位置变化**的标识。

**存档**
- 新增 `archive/` —— 冻结的历史形态，只增不改
- `archive/single-file-v0.7.html`：0.8.0「项目化」之前的单文件版，正文 27 章，
  自包含、离线可读。此前它只存在于主仓库的 `legacy/`，本仓库里没有
- `archive/README.md`：存档规则、版本轴，以及与本仓库范围有关的两处偏离记录

**规范 ID**
- 章节的锚点即其规范 ID，写作 `DOG-<id>`。可以改标题、改内容、移动位置，但不改已有 `id`
- 新增 `scripts/sync-norm-ids.js`，由数据模块生成 `reference/norm-ids.html` 与 `spec/norm-ids.json`
- 登记表从此是生成物而非手写：它随数据变化，并会在**已登记的 ID 消失时**逐条报出、非零退出
- 跨版本引用 SHOULD 用规范 ID，MUST NOT 只用节号

**版本轴**
- 新增 `versions.html`：修订序列、三个互不相干的版本轴、存档入口。已进顶部导航
- 文档修订号收敛到 `assets/js/render.js` 的 `VERSION`，经 `SpecSite.VERSION` 暴露；
  正文页的章数改为实读数据。`spec/dog.html` 的侧栏副标题此前写死 `v0.12`，到 0.13 已经是错的

**协议约定**
- 正文页顶部新增《怎么读这份文档》区块（渲染器新增 `frontMatter` 参数）。它**不重复**
  术语表与 `DOG-conventions`（§2.4）已有的规范强度定义，只说明三条会影响解读的约定
  （引用方式 / 版本轴 / 数字出处）
- 术语表新增《引用与版本》，并修掉一处过期引用：那张表里的「Appendix H」早在 0.9.1
  的字面清理中就该改掉 —— 生命周期现在是正文 `DOG-lifecycle`（§2.8），不是附录 H

**PART 分组与节号**
- 正文分 5 个 PART：`I` 系统概述（6 章）· `II` 接口规范（10 章）· `III` 实测与运维（9 章）·
  `IV` 观测与量化（7 章）· `V` 出处与修订（2 章）。分组写在 `assets/data/dog.js` 的 `parts`
  与各章节的 `part` 字段里，侧栏与正文的 PART 分隔行都由渲染器生成
- 节号由两位全局列号改为 `§X.Y`。**迁移规则（一一对应，可直接推算）**：

  | 旧列号 | 新节号 |
  | --- | --- |
  | `00`–`05` | `§1.1`–`§1.6` |
  | `06`–`15` | `§2.1`–`§2.10` |
  | `16`–`24` | `§3.1`–`§3.9` |
  | `25`–`31` | `§4.1`–`§4.7` |
  | `32`–`33` | `§5.1`–`§5.2` |

- 全仓库 141 处 `§` 引用同步改写（23 个文件）。**不改的两处**：本文件中 0.13 及更早的条目、
  以及 `archive/` —— 前者是历史记载，后者是冻结的存档
- 生成器现在会在节号漂移时逐章报出「旧 → 新」，但**不退出非零**：节号变动本身不是错，
  漏改引用才是。规范 ID 消失才退出非零

## [0.13] — Layout

**Change class:** 仓库结构

**背景**
0.9 到 0.12 四个版本各自往仓库里加了一套东西。加的时候只考虑过「这个文件该挨着谁」，
没有考虑过「这一层是给谁用的」。结果是运行时内核、内容数据、开发脚本与生成物混在同一个目录里：
`assets/js/` 一个目录同时装着 200 KB 的内容数据和 6 个几十行的内核。

这一版**不动任何正文、编号与页面形态** —— 只重排文件、统一命名。

**四层职责**

| 层 | 谁在用 | 目录 |
| --- | --- | --- |
| 运行时资源 | 页面加载 | `assets/`（`data/` 内容 · `js/` 内核 · `css/` 样式） |
| 交互页面 | 读者用浏览器打开 | `spec/` · `reference/` · `tools/` · `sdk/` |
| 开发脚本 | 只有开发时跑 | `scripts/` |
| 文档 | 人读 | `docs/` |

**路径迁移**

| 旧 | 新 | 为什么 |
| --- | --- | --- |
| `assets/js/data-dog.js` | `assets/data/dog.js` | 内容数据与内核分离 |
| `assets/js/appendices.js` | `assets/data/appendices.js` | 同上 |
| `assets/js/charts-dog.js` | `assets/js/charts.js` | 去掉冗余的 `-dog` 前缀 |
| `tools/dog-expression.js` | `scripts/expression.js` | 开发脚本单独一层 |
| `tools/sync-params.js` | `scripts/sync-params.js` | 同上 |
| `docs/expression-sheet.html` | `tools/expression-sheet.html` | 生成物与生成它的工具同处 |

上表均为**移动或改名，文件内容未作改写**（git 记为 rename）。除最后一行外，页面 URL 结构不变。

**新增**
- `docs/expression-geometry.md` —— 表情几何踩坑记录。这份内容此前只存在于
  `.workbuddy/skills/dog-expression/reference.md`，而 `.workbuddy/` 被 `.gitignore` 排除。
  README 的《表情引擎》一节与 CONTRIBUTING 第八条都写着「改几何前先读它」，
  但公开读者到不了那个路径 —— 这一版把它放进 `docs/`，让承诺与事实一致。
- `docs/expression-sheet.html` 保留为一张**跳转页**，指向新位置。

**命名约定**
同一个模块在不同目录里用同一个词干，由目录区分角色 ——
`expression.js`（内核）/ `expression.html`（页面）/ `expression-sheet.html`（生成物）/
`expression.md`（文档）/ `expression-geometry.md`（踩坑记录）。
本仓库只服务 DOG 一个系统，文件名里不再重复系统名，所以 `charts-dog` 与 `data-dog` 一并收进这一条。

**未改动**
正文 34 章、附录 A–R 的字母与编号、页面形态、除上表最后一行外的所有 URL。

**历史条目的路径**
0.13 之前的条目里出现的 `assets/js/data-dog.js`、`assets/js/charts-dog.js`、`tools/dog-expression.js`
等路径记录的是**当时**的位置，未作改写。要找文件，对照上面的迁移表。

## [0.12] — Peripherals

**Change class:** Hardware

**背景**
前 0.9 到 0.11 三版把这份文档里的数字变成了**可计算**的、**可复现**的、**可画出来**的，但都绕开了一个问题：
**这份规范里的系统不接受参数调优 —— 那它到底哪一部分是可插拔的？**

0.12 的答案是**外设**。球、盘、绳、嗅闻垫、漏食器、啃咬物、牵引、冷却垫、笼箱 —— 这些是唯一由你决定「接不接、接哪个、什么时候退役」的部件。
所以这一章把「买玩具」写成了**总线协议**：有分类轴、有角色、有门槛、有失效模式、有端点、有短路规则，也有一个明确的整类弃用。

**新增**
- **正文 §31《外设总线（Peripheral Bus）》**（DOG 33 → 34 章）：三条与其余接口相反的性质（单调递减 / 无鉴权 / 无遥测）、分类轴、六种角色、14 类设备索引、
  序列闭合 MUST、60% 承接上限、13 道门槛、气道门槛、网球案例、生长板分档、硬度门槛、磨损与退役、五类失效模式、5 个端点与两条短路。
- **附录 R《外设目录与安全门槛》**（DOG 17 → 18 附录，A–R）：目录表 14 行、失效模式逐条成因 33 行、门槛依据 13 行、合规声明对照 4 行、弃用清单 2 行，外加一份可打印的选购与完整性核对表。
- **外设内核** `assets/js/peripherals.js` —— `14` 类 · `6` 种角色 · `5` 阶段序列 · `13` 道门槛 · `33` 种失效模式 · `15` 条来源。纯函数，浏览器与 Node 通用，零依赖、零网络。
- **外设控制台** `tools/peripherals.html` —— 左侧填档案与清单，右侧实时出结论：序列闭合检查、配额承接、DNS 增量、HRI 抑制、逐设备门槛、磨损预测、合规状态、可复制的 JSON。
- 入口接线：`index.html` 新增「外设」区（3 张卡 + 统计行 + 顶部按钮）、`assets/js/render.js` 的 `NAV` 新增「外设总线」、
  README 新增《外设总线》与《添加一个设备类》两节、`spec/dog.html` 副标题更新。

**设计决定（四条，全部写在页面上）**
1. **按捕猎序列分类，不按材质。** 材质只决定耐磨，序列决定它在满足哪一相。同样「用嘴咬」的两样东西，一样能用很久，另一样能把牙崩断 —— 这个差别不在材质，在它服务的是哪一相。
2. **序列闭合是 MUST，不是 SHOULD。** 只提供早期阶段（定向 / 潜行 / 追逐）而不提供终点（咬合 / 撕解）的配置会持续累积未完成的序列。
   这是**激光笔被整类弃用**的唯一理由，而不是「使用不当」；它的迁移目标是拉力杆（`PER/FP`），因为后者提供同一个追逐相**并且**给出终点。
   这与 `dog_age × 7` 的弃用性质不同：那一条是被更好的算法取代，这一条是被承认 —— 这个接口从第一版起就不应该存在。
3. **60% 是算出来的，不是定的。** 内核不含第二份配额数据：承接上限由 `DogQuant.DNS_DIMS` 的五维权重实时加总 —— 运动 25 + 嗅闻 20 + 认知 15 = **60% 可承接**；
   社交 20% 是**结构性缺口**（它在引擎里的定义是「直接互动 60 分钟，共处一室不计入」，一个能替你做掉它的外设按定义就不是外设）；休息 20% 只能被**承载**，不能被替代。
4. **不知道就说不知道。** 气道门槛只覆盖气管受压，不覆盖舌根嵌顿 —— 后者没有公开的定量表，于是只给操作判据、不给数字；
   磨损区间只给绳、橡胶、工程材料三类（零售侧观察区间，C 级），其余材质一律返回「本项目不给数值」，而不是编一个天数。

**与既有内核的关系**
- 两条短路沿用 §29 的既有规则，不新造：**热风险硬停**（气温 ≥32 ℃ 或 HRI ≥10 时户外外设全部挂起）与**分诊短路**（`P0` / `P1` 时外设端点返回 `451`）。
- `lineup()` 实时调用 `DogQuant.dns()` / `hri()` / `triage()`；控制台里的 DNS 增量、HRI 下行与分诊标记**没有一处是页面写下的数字**。
- 气道门槛 = 临床气管插管尺寸表（**B 级**）× `1.5` 系数（**C 级**，本项目推导），短鼻品种再乘 `0.85`。正文明确写了它「是必要条件，不是许可证」。

**校验结果**
- **12 个 JS 文件**通过 `node --check`（新增 `peripherals.js`）
- **内核断言**通过：覆盖率求和 = 1；13 道门槛全部注册；序列规则**确实**否掉激光笔（ban + 未闭合）；气道表随体重单调递增；每一处弃用都有真实存在的迁移目标

- **DOM 桩冒烟**：`tools/peripherals.html` 的内联脚本在无浏览器环境下执行通过，**20 段渲染输出无 `undefined` / `NaN` / `Infinity`**，
  页面标题自检串输出为「14 类 / 13 门槛 / 可承接 60%」——三者与内核实算一致
- **渲染冒烟**：DOG **34 章 + 18 附录 = 52 个锚点**，无重复、无 `undefined`／`NaN` 残留，`table`／`pre`／`blockquote` 标签全部配平
- **链接自检**：全站 **79 条**站内链接（含锚点）**0 死链**；其中 4 条指向运行时生成的章节锚点
- **来源**：内核 `15` 条来源条目，附录 R 的选区/门槛/失效模式逐条标注 A / B / C

**修正：13 处过期的「附录 R」标注**
公开信源从 0.8 起改为**正文章节**（现为 §32《公开信源》）后，仍有 13 处**旧标注**把它称作「附录 R」
（`index.html` 2 处、README 2 处、`docs/CONTRIBUTING.md` 3 处、`data-dog.js` 的 6 行修订记录）。
0.9.1 已经为同类问题立过规矩：**旧附录字母会与实际自动编号冲突，一律改为纯章节名**。
本版按同一条规矩处理 —— 因为 R 这个字母**现在归外设目录**，留着旧标注会让读者点开附录 R 看到一份玩具清单。
另修正一处工具缺口：`check-site.js` 的运行时锚点收集只认带引号的键（`"id":`），漏掉了 `appendices.js` 用的裸键（`id:`），

**备注**
本章最容易被误读的一节是「合规空白」。宠物玩具在美国**没有强制性标准**（CPSC 只监管会伤害人类的产品，`ASTM F963` 约束的是儿童玩具），
所以内核把它记为 `warn` 而**不是** `fail`。正文的写法是：*有，说明厂商花过钱；没有，什么都不是。*

## [0.11] — Charts

**Change class:** Presentation

**背景**

这一版补的是最后一米：**让数字被画出来，而不是被做成插图。**

- 入口接线：`index.html` 新增「图表」区（3 张卡 + 统计行 + 顶部按钮）、`assets/js/render.js` 的 `NAV` 新增「图表图鉴」、README 新增《图表图鉴》与《添加一张图表》两节。

**设计决定（四条，全部写在页面上）**
1. **字体内联为字体栈。** Lieflat 用 Google Fonts 引 Inter；本项目首要约束是所有页面必须能直接双击打开，所以 `'Inter','PingFang SC',…,sans-serif` —— 装了就用、没装安静回落，**不发网络请求**。也因此 19 张图**全部手写 SVG**，没有取该库里依赖 CDN 的 ECharts / Chart.js 图型。
2. **K 线不用涨跌色。** 跟随 Lieflat 的灰阶语义：实心墨 = 收跌、空心 = 收涨。体重不是股价，于是也不存在「本项目默认涨红跌绿」与图库约定打架的问题。整页锁死**一种色彩系统**，唯一的暗卡是第 12 张。
3. **取整要认账。** 第 4 张把 1440 分钟折成 100 格、六段百分比取整后只有 99，差额**显式**记在「独处 / 其余」上，底注写明「分钟数是真的，格数是取整的」。第 6 张的瀑布每项取到 0.5 的整数倍，合计 13.5 与引擎的 13.5 一致，没有欠账。
4. **极值不画，而不是断轴。** 第 9 张的 K 系数里工作犬是 5–11，是一根把其余七行全压扁的柱子；既然柱的契约是长度 ∝ 数值，这里选择**不画那一行并在副标题说明原因**，而不是截断坐标轴。

**数据层不另抄一份常量。** 能量、饮水、配额、热风险 HRI、就诊应激 VSI、分诊优先级、生命阶段、DNS 权重逐项实时调用 `DogQuant`；表情四维取自 `DogExpression.stateParams()` 的真实向量。合成示意数据一律在来源行标注为 **C 级**。来源等级分布：**A 4 · B 2 · C 13**。
