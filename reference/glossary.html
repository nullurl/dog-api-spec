REFERENCE / GLOSSARY

术语表

本页收录跨文档共用的约定。专有术语见 DOG API 各附录。

符号约定

=     文档内定义或赋值
≈     结构类比；不声明底层机制或协议等价
->    映射、路由或因果方向；强度由 Context 决定
!=    禁止自动 Cast 的关系
§     章节定位符；跨修订版本不保证稳定

规范强度

MUST强制约束。违反即为缺陷，不是风格问题。
SHOULD推荐实现，允许 Context-specific Exception。
MAY可选实现。做了不加分，不做不扣分。
HEURISTIC社区经验值，无实验支撑。本文档凡用此项必予标注。
DEPRECATED已废弃，但仍在民间广泛流传。例：dog_age × 7。
WON'T FIX已确认为特性。多数维护者最终选择保留。

核心术语

术语定义
Instance一个独立部署的个体实例
Keeper / 维护者承担运维责任并持有运维权限的主体
Reward Source产生或控制强化信号的节点
Runtime当前正在执行的全部前台与后台过程
Capacity特定 Runtime 下实际可用的资源
Permission对某一接口或资源的访问权
Trust降低重复认证成本的长期凭证
Projection某个系统对实例的局部表示，不等于实例本身
Rate Limit可持续承受的调用上限
Endpoint可被外部路由或调用的接触面，不要求等同于 URI
Appendix H生命周期 Changelog，不等于文档版本
Sniff-Handshake实例间身份核验；约 15 秒完成全量信息同步

禁止自动 Cast 的关系

以下写法在本项目的任何文档中都不成立。这一节是整套规范的公共安全阀。

Projection   != 实例本身
Score        != Intelligence
Online       != Available
Read         != Ready to Respond
Close        != Unlimited Permission
Metric       != Objective

Difference   != Harm
Mismatch     != Violation
Adaptation   != Consent
Stability    != Fairness
Compliance   != Legitimacy

摇尾巴       != 友好          // 需结合全身姿态与 Context；左偏常对应退缩
吃草         != 系统故障
拆家         != 恶意          // 多为资源未调度：运动量不足导致算力溢出
蹭腿         != 饿            // 可能是路由标记
眯眼         != 睡着          // 很可能是监控
露出肚子     != 授权          // 陷阱式接口

"乖"         != 它的义务      // 是你单方面定义的 KPI
"听话"       != 爱的证据
被独自留下   != 它能理解的事  // 它从未理解过，只是学会了等待

POWER CHECK

用于检查模型的遗漏，不预设 Harm、Violation 或 Unfairness 已经发生。

谁定义了规则？
谁承担了适配成本？
被适配的一方，能否有意义地拒绝？

DOG 侧的答案：

DOG     —— 规则由维护者定；适配成本几乎全部由 Dog 侧承担；它从未申请过任何权利
术语的用处不是把生物说成机器，而是看清：机器不会这样对你，而它们会。
