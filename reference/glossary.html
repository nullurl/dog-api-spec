术语表

本页收录跨文档共用的约定。专有术语见 DOG API 各附录。

符号约定

=     文档内定义或赋值
≈     结构类比；不声明底层机制或协议等价
->    映射、路由或因果方向；强度由 Context 决定
!=    禁止自动 Cast 的关系
§     章节定位符；跨修订版本不保证稳定
      —— 引用别的版本时请改用规范 ID，见 reference/norm-ids.html

规范强度

MUST强制约束。违反即为缺陷，不是风格问题。
SHOULD推荐实现，允许 Context-specific Exception。
MAY可选实现。做了不加分，不做不扣分。
HEURISTIC社区经验值，无实验支撑。本文档凡用此项必予标注。
DEPRECATED已废弃，但仍在民间广泛流传。例：dog_age × 7。
WON'T FIX已确认为特性。多数维护者最终选择保留。

术语定义
Instance一个独立部署的个体实例
Keeper / 维护者承担运维责任并持有运维权限的主体

引用与版本

本项目里同时存在几个都叫「版本」的东西，它们数值上互不相关。引用之前先分清你要引的是哪一个：

轴谁在记录跨版本是否稳定
文档修订（0.1.0 → 0.23）历史版本它就是版本编号本身
规范 ID（如 DOG-peripherals）规范 ID 登记表稳定 —— 取自章节锚点，一经分配不再更改
节号（§4.7 · 附录 R）运行时按数组顺序生成不稳定 —— 任何插入或删除都会让其后的编号整体平移
系统运行版本正文 DOG-lifecycle（§2.8）与本项目无关

跨版本引用 SHOULD 用规范 ID，MUST NOT 只用节号。这不是一条风格建议：附录字母按数组位置派生， 中间删掉一条会使其后所有字母整体前移，全站十几处「附录 X」引用会同时失效 —— 本项目真实发生过一次， 当时的处理方式是就地改写内容、保持字母不动。节号同理，本项目已经整体改过一次号 （0.14 起由两位列号改为 §X.Y，迁移规则见 CHANGELOG 的 0.14 条目）。

确实要写节号时，SHOULD 同时写出规范 ID，例如「§4.7 外设总线（DOG-peripherals）」。

术语的用处不是把生物说成机器，而是看清：机器不会这样对你，而它们会。
